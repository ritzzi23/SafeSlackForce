# Report and browser follow-up — 1 October 2026

The previously incomplete browser check is now complete. Report generation also
saved a sourced model-written report from the actual rehearsal history without
using the structured fallback.

## Report changes

The rehearsal contains 194 timeline entries. The old fixed page size required
eight history reads, exceeding the default five model rounds even before the
incident read and report save. Repeated source metadata also inflated context.

History pages now use a 36,000-character bound with a source dictionary per page.
Event IDs, timestamps, complete text, source IDs, confirmation labels and URLs are
preserved. The model context ceiling is explicitly bounded at 100,000 characters;
the configured round, call and dollar limits still apply. Larger histories or
individual entries that cannot fit continue to use the labelled structured fallback
in autonomous mode, retaining the full persisted timeline in the report.

The model is offered `save_report` only after it reads the incident and every
current history page. Server-side validation remains authoritative. A new incident
revision invalidates old history coverage, so rereading only the incident cannot
authorize a report based on the older timeline.
